# DrawIt — Spec (v1)

Oct 23, 2026 · @Shardul

## 1. Overview

DrawIt is a local-only, canvas-first diagram and infographic tool. It runs as a web app in any desktop browser, served by a single local binary on any OS, and saves diagrams as readable text files that diff cleanly.

- **Name:** DrawIt is the internal working name; the public name is chosen before public release.
- **Canvas-first:** people draw on the canvas; the file is the storage format, not the authoring surface. Positions are pixel-exact and stored in the file.
- **Diagram as code:** files diff cleanly, are safe to hand-edit, and can be generated by scripts or LLMs. Files do not need to be in git.
- **Privacy:** no network access at runtime. Nothing leaves the machine.
- **Diagrams and infographics:** boxes-and-arrows diagrams plus designed visuals with styled text, images and an extensive shape library.
- **Scale:** hundreds of elements per diagram.
- **Extensible:** a small core plus data-only shape packs; a plugin API for code extensions follows after v1.
- **Platform:** desktop browsers with mouse and keyboard. English text and UI.
- **Audience:** the author and colleagues first; public and open source (AGPL-3.0) from day one.
- **Development:** test-first, AI-assisted. Work is tracked in `tickets.md`; reasoning behind decisions is in `decisions.md`.

## 3. Shape library

The shape library is categorised and searchable, in the left sidebar. Shapes ship as data-only packs: SVG plus a manifest per shape defining its outline, stretch behaviour, label area, and connection points.

| Category | Shapes |
| --- | --- |
| Basic | Rectangles, rounded rectangles, circles, ellipses, diamonds, triangles, polygons, stars, callouts, brackets |
| Flowchart | Process, decision, terminator, data, document, manual input, connectors |
| Architecture (generic) | Server, database, cache, queue, CDN, load balancer, API gateway, DNS, firewall, storage bucket, function, container, client, browser, mobile, user, cloud |
| Network | Router, switch, VPN, internet, subnet, on-prem |
| C4 | Person, software system, container, component, boundary |
| Infographic | Badges, banners, numbered steps, timeline markers, ribbons |
| Arrows and lines | Block arrows, curved arrows, brackets, dividers |

- **Creating:** the sidebar lists shapes by category, with search over names and tags and a preview of each. Clicking a shape arms it; a click on the canvas places it at its default size and a drag sizes it. Rectangle and ellipse are built in and listed alongside the pack shapes.
- **Unknown shapes:** a node that names a shape no pack provides is drawn as a dashed placeholder showing the shape name, at its layout size or, when the layout gives no `w` and `h`, at the standard default size, and is kept in the file untouched.
- **Selecting:** a click selects a shape inside its outline or within a few screen px of it; drag-box uses bounding boxes.
- **Original shapes only:** no vendor icon sets (AWS, GCP, Azure) are bundled.
- **Growth:** packs are added and extended without changes to the core.
- **Packs:** `core` (basic, flowchart, arrows and lines; names need no prefix), `arch`, `net`, `c4`, `info`.
- **Pack folder:** `packs/<pack>/` holds `pack.json` (JSON) and one SVG per shape. The folder is named after the pack id; a shape's full name is `<pack>.<id>`.
- **Manifest:** per shape: `id`, `name`, `category`, `tags`, `svg` (file name), `size` (`{ w, h }`, the default size), `outline`, `anchors`, `label`, `stretch` and `keepAspect`. All coordinates are in the SVG's own space, `0 0 w h` at the default size.
  - `outline` is one closed path used for hit-testing and for attaching edges anywhere along the shape's edge.
  - `anchors` are the default attach points for `auto`: `top`, `right`, `bottom` and `left`, each a point on the outline (the side midpoint, or where the outline meets the side's centre line), plus an optional `extra` list.
  - `label` is the rectangle where text is centred.
- **Stretch:** optional x and y cut lines, two per axis (`"stretch": { "x": [a, b], "y": [c, d] }`). Parts outside them keep their size and move; parts between them scale. A target narrower than the fixed parts shrinks them together. With no cut lines the whole shape scales. `keepAspect` locks the ratio, as for icons, and excludes cut lines. A circle or ellipse lies inside one zone of each stretched axis.
- **SVG rules:** only `path`, `rect`, `circle`, `ellipse`, `polygon`, `line`, `polyline` and `g`. No text, filters, images, styles, scripts or external references. Paths use absolute `M`, `L`, `H`, `V`, `C`, `Q` and `Z`. No literal colours: each element has a role in `data-role` (`fill`, `stroke` or `detail`) and takes its colour from the theme and classes. A `fill` part takes the element's fill, a `stroke` part its stroke, and a `detail` part its stroke, drawn at two thirds of the stroke width. Stroke width comes from style.
- **Look:** flat outline plus fill, round joins and caps, an 8px design grid, default sizes in multiples of 8. Icon shapes share one canvas size and level of detail. Containers share one corner radius.
- **Validation:** `pnpm validate:packs` checks every pack for schema, allowed elements and attributes, literal colours, roles, a closed outline, anchors on the outline and inside the shape's bounds, a label inside the bounds, and cut lines.
- **Contact sheet:** `pnpm contact-sheet` writes one page showing every shape at its default size, stretched wide and narrow, in light and dark, with a view of its outline, anchors and label area. It draws each part by the same role rules as the app, including `detail` in the stroke colour at two thirds of the stroke width.

## 4. File format

### 4.1 Principles

1. **KDL v2** is the base syntax; DrawIt defines the schema on top.
2. **Three sections in one file.** Structure holds meaning and content. Style holds appearance. Layout holds geometry.
3. **Each kind of edit touches one line.** Editing text changes structure; recolouring changes style; dragging changes layout; changing z-order moves a layout line.
4. **The app is the formatter.** Every save rewrites the file in canonical form; hand edits are normalised on the next save.
5. **The document model is the source of truth.** Only the model is written to disk.
6. **Versioned.** Every file declares a schema version and the plugin versions it uses; the app migrates older versions forward.
7. **File name:** `<name>.drawit.kdl`. Assets live in an `assets/` folder next to the file.

### 4.2 Example

```kdl
diagram version=1 title="Order flow" {
  plugins core@1 arch@1
}

// ── structure ─────────────────────────
frame overview "Overview"

text headline "Orders grew 42% in Q3" class=accent

node api "API Gateway" shape=arch.gateway
node orders "Order Service" shape=arch.server class=critical

shape backend shape=rect class=boundary
text backend-title "Backend"
node db "Orders DB" shape=arch.database
node queue "Events" shape=arch.queue

edge api orders label="POST /orders"
edge orders db
edge orders queue id=publish

image logo src="assets/logo.svg"

// ── style ─────────────────────────────
style {
  theme default {
    color primary="#1F4E79" accent="#E8732A" ink="#1A1A1A"
    font heading=Inter body=Inter
    size h1=36 body=14
  }
  class accent color=$accent weight=700
  class critical stroke=$accent stroke-width=2
  class boundary stroke=$primary dash=dashed
  el headline font=$heading size=$h1
  el backend-title weight=700
  el publish dash=dashed route=elbow head-end=arrow
}

// ── layout (managed by app) ───────────
layout {
  overview x=0 y=0 w=720 h=640
  headline x=40 y=24 w=600
  logo x=600 y=24 w=80 h=40
  backend x=240 y=260 w=420 h=200
  backend-title x=256 y=268
  api x=40 y=150 w=160 h=60
  orders x=280 y=150 w=180 h=60
  db x=260 y=320
  queue x=480 y=320
  publish via="480,230 520,290" from=right to=top:0.5
}
```

### 4.3 Structure section

Structure records what exists, what it says and how things connect.

- **Header:** `diagram version=<int> [title=…] { plugins <id>@<version>… }`.
- **IDs:** short, human-readable slugs matching `[a-z][a-z0-9_-]*`, unique across the file; all element types share one namespace. IDs join structure to style and layout. Renaming an ID in the app updates all three sections and enforces the pattern. Default edge IDs (`from->to`) are derived; the formatter quotes any ID that KDL requires to be quoted.
- **Flat structure:** every element is a top-level entry.
- **Node:** `node <id> ["label"] shape=<pack.name> [class=<name>]`. The label is the first argument and defaults to the ID. It is plain text in one style; line breaks are allowed. `core` shapes may omit the pack prefix.
- **Frame:** `frame <id> ["name"]` is a named region on the canvas, used for export.
- **Edge:** `edge <from> <to> [id=…] [label=…] [class=…]`. Each end is an element ID, or `-` for an end attached to nothing, whose point is in layout. The default ID is `from->to`; an explicit `id=` is required when two edges join the same pair or an end is `-`, and the formatter adds it. The label is plain text.
- **Text:** `text <id> "content" [class=<name>]` is a free text box. The content is plain text; line breaks are written `\n`.
- **Image:** `image <id> src="assets/…"` references a raster or SVG file by relative path. Nothing is embedded as base64.
- **Shape:** `shape <id> shape=<pack.name>` is a decorative shape without label semantics.

### 4.4 Style section

Style holds all appearance.

- **Theme:** `theme <name> { color …; font …; size …; space … }` defines named tokens. v1 has one theme.
- **Tokens:** values written as `$name` resolve from the theme (`fill=$primary`).
- **Classes:** `class <name> <props…>` defines reusable styles, referenced from structure.
- **Per-element overrides:** `el <id> <props…>` sets appearance for one element. Every line in this section starts with a keyword (`theme`, `class`, `el`), so an ID can never be mistaken for one, and plugins can add keywords without breaking existing files.
- **Resolution:** properties merge in the order built-in defaults for the element kind, then the element's class, then its own `el` override; the last to set a property wins. Then each `$token` is replaced from the file's theme, which is a dictionary of tokens and not a layer of properties. A well-known token that the file's theme lacks takes the built-in theme's value; a token that nothing defines leaves the property unset, so the element shows its default for it.
- **Well-known tokens:** the built-in default theme defines these, and a file's theme may redefine them or add more.

| Kind | Tokens and built-in values |
|---|---|
| Colours | `primary` #1f4e79, `accent` #e8732a, `ink` #1a1a1a, `paper` #ffffff, `surface` #dbe8f5, `line` #1f4e79 |
| Fonts | `body` Inter, `heading` Inter, `mono` JetBrains Mono |
| Sizes | `small` 12, `body` 14, `h3` 18, `h2` 24, `h1` 36, `stroke` 1.5, `leading` 24 |
| Spaces | `sm` 4, `md` 8, `lg` 16 |

- **Default look:** what an element has when nothing in the file sets a property. `paper` is the background behind edge labels.

| Property | Node | Shape | Text box | Edge |
|---|---|---|---|---|
| `fill` | `$surface` | `$surface` | none | none |
| `stroke` | `$line` | `$line` | none | `$ink` |
| `stroke-width` | `$stroke` | `$stroke` | none | `$stroke` |
| `dash` | `solid` | `solid` | none | `solid` |
| `radius` | 0 | 0 | 0 | none |
| `opacity` | 1 | 1 | 1 | 1 |
| `shadow` | none | none | none | none |
| `font` | `$body` | none | `$body` | `$body` |
| `size` | `$body` | none | `$body` | `$body` |
| `weight` | 400 | none | 400 | 400 |
| `italic`, `underline` | off | none | off | off |
| `color` | `$ink` | none | `$ink` | `$ink` |
| `align` | `center` | none | `left` | `center` |
| `line-height` | `$leading` | none | `$leading` | `$leading` |
| `route`, `head-start`, `head-end` | none | none | none | `straight`, `none`, `arrow` |

- **Values:** `radius` applies to the built-in rectangle and to text boxes; a pack shape takes its corners from its cut lines.
  - `dash` is `solid`, `dashed` or `dotted`.
  - A gradient `fill` is written as one quoted string, `"linear(<angle>, <stop>, <stop>…)"`: an angle in degrees and two or more stops. A stop is a colour or a colour token, optionally followed by a position from 0 to 1 (`$accent 0.7`); a stop with no position is spaced evenly between its neighbours.
  - `shadow` is one quoted string, `"<dx> <dy> <blur> <colour>"`, one per element; the colour may be a token.
  - The formatter prints these strings with one space after each comma or between fields, an integer angle, positions and numbers without trailing zeros, and colours and tokens as written. A value that does not parse is kept as written and skipped when drawing.

| Group | Properties |
| --- | --- |
| Fill | `fill` (colour or gradient), `opacity` |
| Stroke | `stroke`, `stroke-width`, `dash`, `radius` |
| Effects | `shadow` |
| Text | `font`, `size`, `weight`, `italic`, `underline`, `color`, `align`, `line-height` |
| Edge | `route` (`straight`, `elbow`), `head-start`, `head-end` (`arrow`, `dot`, `none`) |

- **Fonts:** three font families bundled with DrawIt (Open Font License): Inter, Source Serif 4 and JetBrains Mono, each with regular, bold and italic; no other fonts. Exports embed the fonts they use. No font CDN.
- **Plugin properties (after v1):** code plugins register additional typed properties. In v1 the properties are the ones listed here, and the validator knows each of them.

### 4.5 Layout section

Layout holds geometry only: one line per element, keyed by ID, owned by the canvas.

- **Position and size:** `x`, `y` required; `w`, `h` optional, falling back to the shape default. A text box uses only `w`: without it the box fits its content, with it the text wraps there, and the height is always the wrapped lines. Integers, in px at 1x zoom. Coordinates are absolute canvas positions.
- **Lock:** `locked=#true`, optional.
- **Edge anchors:** `from` and `to` take `auto` (default; nearest side, recomputed on move) or a side (`top`, `right`, `bottom`, `left`), optionally with a position along it: `left:0.3`.
- **Free ends:** `from-point="x,y"` or `to-point="x,y"` for an end written as `-` in structure.
- **Bend points:** `via="x,y x,y …"`.
- **Edge label position:** `label-at=<0..1>` along the path.
- **Z-order:** the order of entries; later entries draw on top. Nodes and edges share one order. New elements are appended, so they draw on top; bring to front and send to back move an entry.
- **Missing entries:** elements without a layout line are placed on open in a grid, in file order, left to right, wrapping at 1200px, at each shape's default size with 80px between them. Their positions are written on save. Edges without anchors use `auto`. The in-app documentation tells authors, human or AI, to write a layout section.
- **Orphan entries:** lines for IDs no longer in structure are dropped on save.

### 4.6 Canonical formatting

Every save produces the same bytes for the same diagram.

- **Section order:** header, structure, style, layout.
- **Structure order:** as authored; new elements are appended to the file.
- **Layout order:** is z-order and is never re-sorted; new elements are appended.
- **Property order:** fixed per element type.
- **Numbers:** integers for coordinates and sizes.
- **Whitespace:** two-space indent, a single space between fields, no column alignment, one blank line between top-level blocks.
- **Comments:** whole-line `//` comments attach to the element below and move with it. End-of-line and block comments are dropped on save, with a one-time warning.
- **Unknown content:** nodes and properties from packs or plugins that are not installed are kept losslessly in content, re-emitted in canonical KDL with their formatting normalised, and drawn as placeholders.

### 4.7 Reserved for later versions

- `icon <id> icon=<pack.name>`: an icon from an icon pack.
- `chart <id> type=chart.<kind> [title=…] { row <label> <value…> }`, with `data="assets/<file>.csv"` for larger datasets. A chart is one element in layout.
- `rotate=<degrees>` in layout.
- Rich text in text boxes: a Markdown subset (`**bold**`, `*italic*`, `__underline__`, line breaks) plus Pandoc-style spans, where `[42%]{.accent}` applies a class and `[text]{color="#f00"}` applies a raw override. Spans are applied last in the resolution order.

## 5. Editor

### 5.1 Interface

A minimal canvas with floating toolbars.

- **Toolbar:** select, rectangle, ellipse, line/arrow, text, image, frame; undo/redo; zoom; unsaved indicator.
- **Left sidebar:** tabs for the workspace file tree, the shape library, and an outline list of all elements in z-order.
- **Right panel:** properties of the current selection: fill, stroke, text, arrange, position, size.
- **Status bar:** zoom, cursor position, grid and snap toggles.
- **Command palette:** Cmd/Ctrl+K lists every action with its shortcut.
- **Configuration:** every panel and toolbar can be shown or hidden from View or Preferences; every action has a configurable shortcut. Preferences are stored in one file in the OS user config directory.
- **Documentation:** an in-app reference covers the file syntax, section by section, with examples, the shape names and the style properties. It is written for people and AI authors, so they can check what a file should contain and what they may have written wrong.

### 5.2 Canvas and selection

- Click, shift- or Cmd/Ctrl-click and drag-box selection; select all.
- Move and resize with handles. Arrow keys nudge 1px, or 10px with Shift.
- Snapping to the grid.
- Elements move together by multi-selecting them. Dropping an element over another changes neither.
- **Select inside:** a command selects every element fully inside the selected shape or frame, so a container can be moved or copied with its contents. Edges with both ends among the selected elements are included; locked elements are skipped. A boundary, such as a subnet or a swimlane, is an ordinary shape drawn behind its contents.
- Locked elements cannot be moved or selected by drag-box.
- A drag is transient until release and commits as one command.

### 5.3 Connectors

- Edges attach to any element: shapes, text, images. Moving or resizing an element re-routes its edges.
- Anchors default to `auto`; a fixed side or a point along a side is explicit.
- Routing is straight or elbow. Manual bend points are kept; endpoints always recompute.
- Arrowheads at either end.
- **Edge labels:** a label is centred on the point `label-at` of the way along the path (the middle when absent) and moves with the path. It is drawn over a background in the canvas colour, in one line per line break, and is never wrapped. The label's box counts as part of the edge for clicks. A lone selected edge shows a grip over its label: dragging it sets `label-at` to the nearest point of the path, in hundredths, as one command, and Escape cancels. A locked edge's label cannot be dragged.
- **Drawing:** with the line tool, drag from an element or from empty canvas to an element or to empty canvas. An end on an element is attached with an `auto` anchor; an end on empty canvas is a free end. The new edge is selected and the tool returns to select. Dragging from an element to itself draws nothing.
- **Selecting:** a click within a few screen px of an edge's path selects it, and a lone selected edge shows a handle on each end. Edges and shapes share one z-order for clicks. Drag-box selects every edge it touches; select all includes edges; locked edges are skipped by both.
- **Moving:** moving elements also moves the bend points and free ends of a selected edge and of an edge with both ends on the moving elements. An edge with an end that stays keeps its bend points.
- **Re-attaching:** dragging an end handle of the selected edge onto an element attaches the end there, at the side and position along it nearest the pointer, never `auto`; dragging it onto empty canvas or a frame makes it a free end at the pointer. The edge keeps its ID and its bend points, and the other end is unchanged. Dropping onto the element at the other end, or leaving the end where it was, changes nothing; a locked edge cannot be dragged. Escape cancels the drag.
- **Bend points:** a lone selected edge shows a handle on each bend point. Alt-click on its path, within a few screen px, adds a point there, placed in the list by its position along the path. Dragging a handle moves the point; Alt-click on a handle removes it, and removing the last one leaves the edge with no `via`. Each edit is one command, and Escape cancels a drag. Alt-click on an edge that is not selected only selects it, and a locked edge cannot be edited. Double-click is never a connector gesture: it edits text.
- **Attaching to a shape from a pack:** a side and position such as `left:0.3` means the point where a line from that spot on the shape's bounding box, running straight inward, first meets the outline; where it meets none, the point on the bounding box. Auto anchors use the shape's manifest anchors. An elbow route leaves that point along the direction of the bounding-box side it is attached to.
- Deleting an element detaches its edges: each attached end stays where it was, as a free end.

### 5.4 Text

- Text lives in two places. A **shape or edge label** is one per element, centered in the shape's label area. A **text box** is a separate floating element placed anywhere. Both are plain text with one style per element.
- Double-click a shape or edge to edit its label in place; an edge with no label starts an empty one, and an edge whose label is emptied has no label. Double-click empty canvas to create a text box right there; double-click a text box to edit it.
- While editing, the text is shown in a plain editor over the element, on the same lines as the drawn text. Enter adds a line break. Escape, Cmd/Ctrl+Enter or a click elsewhere ends editing and keeps the text. A text box with no text is removed. Typing is grouped by pauses into undo steps, and undo and redo work inside the editor.
- Formatting applies to the whole element and is stored in the style section.
- Text boxes auto-size to content or have a fixed width and wrap.
- Text renders as SVG with DrawIt's own line-breaking, measured with the canvas text API. Lines break only at spaces; a word wider than its box is split between characters found with `Intl.Segmenter`. SVG text and the canvas both use `text-rendering: geometricPrecision`. Editing uses an overlay that measures text identically. `foreignObject` is not used.

### 5.5 Undo and redo

- Every change is a command producing forward and inverse patches (Immer).
- A drag, multi-selection move or paste is one step; typing is grouped by pauses.
- Undo and redo restore the selection.
- History is per open file and lasts for the session.

### 5.6 Workspace, files and saving

- DrawIt opens a folder as its workspace. Everything it reads, writes or exports stays inside that folder, apart from the preferences file (5.1).
- The file tree supports new, rename and delete. Open files appear as tabs.
- Saving is explicit (Cmd/Ctrl+S). Each tab shows an unsaved indicator; closing with unsaved work shows a warning.
- A file changed on disk with no unsaved edits reloads as one undoable command. With unsaved edits, DrawIt asks whether to keep the edits or reload; it never merges.
- A file that fails to parse as KDL is refused with the error and its line and column. It is never opened partially and never overwritten.
- Beyond KDL syntax, DrawIt does not validate hand-edited files; it draws what it can. Everything DrawIt writes is valid.
- DrawIt recognises its own saves by content hash, so they never count as changes on disk.

### 5.7 Clipboard

- Copy and paste any element or multi-selection, within a file or across files.
- Pasted elements get fresh IDs. Edges between copied elements are kept; an edge with only one end copied keeps that end, and the other becomes a free end, moved along with the pasted elements.
- Classes used by pasted elements are copied into the target file if missing.
- The clipboard holds KDL text.

### 5.8 Export

- **SVG:** the canvas, a selection or a frame, with used fonts embedded and a title and description.
- **PNG:** the canvas, a selection or a frame, at 1x, 2x or 3x, with an optional transparent background.

## 6. Architecture

### 6.1 Runtime

One TypeScript app runs in any desktop browser and talks only to a local Go binary that serves it and owns all file access.

- **Document model:** plain TypeScript with no UI: structure, style, layout, KDL read/write, formatter.
- **Commands:** the only way the document changes; the basis of undo/redo and of all plugin actions.
- **Renderer:** SVG. It draws the model and turns pointer input into commands; it never owns state.
- **Storage adapter:** one interface over the local server's HTTP API.
- **Local server:** one static Go binary per OS (macOS, Linux, Windows) with the web app embedded via `go:embed`. Running it starts the server and opens the browser. It handles file reads, atomic writes and file watching.

### 6.2 Local server security

- Listens on `127.0.0.1` only.
- Generates a random session token at startup and opens the browser at a URL carrying it in the fragment, also printed to the terminal. The page keeps it in `sessionStorage`, removes it from the address bar and sends it as an `Authorization` header; requests without it are rejected.
- Checks `Host` and `Origin` headers.
- Serves a strict content security policy (`connect-src 'self'`), so neither the app nor its plugins can reach the network, and `Referrer-Policy: no-referrer`.
- Reads and writes only inside the opened folder, enforced with Go's `os.Root` so symlinks cannot lead out of it. The one exception is the preferences file in the OS user config directory.

### 6.3 Packs and plugins

Packs and plugins add vocabulary; they never change what existing syntax means.

- **Core (always on):** document model, KDL read/write, formatter, commands, undo, the three sections, theme and tokens, primitives (rectangle, ellipse, line, text, image, frame, edge), SVG and PNG export.
- **Packs (v1):** data only (SVG plus manifest): shape packs and themes. Packs are bundled with the app and always on.
- **Extensions (after v1):** code that adds element types, canvas tools, layout engines, importers and exporters.
- **Declaration:** the `plugins` header lists the packs and plugins a file uses, with versions. The app keeps and writes the header; in v1 it does not act on it, and it is the hook for enabling and version checks when code plugins arrive. A shape no pack provides is drawn as a placeholder (section 3) and kept losslessly.
- **Manifest:** id, version, API version, kind, dependencies, and what it provides: shapes, element types, commands, typed style properties.
- **Boundaries:** packs and plugins import only from the public `plugin-api` package; render functions return SVG node trees, never DOM; documents change only through commands.
- **Source:** all packs and plugins are in-house. No marketplace, network access or auto-updates, and no user pack folder in v1.
- **First-party extensions** use the same public `plugin-api` as any other plugin; charts are the first.
- **Charts (after v1):** hand-rolled SVG using d3-scale and d3-shape for the maths only, styled by the theme.

## 7. Quality

### 7.1 Performance budgets

Each budget is an automated test against generated 500-element files.

| Action | Budget |
| --- | --- |
| Open a 500-element file | under 1 second |
| Drag, resize, pan | 60fps (16ms per frame) |
| Save | under 200ms |
| 1,000 elements | works, may slow down |

### 7.2 Accessibility

- Every action is reachable from the keyboard.
- Exported SVGs carry a title and description.

### 7.3 Testing

- Development is test-first. A ticket is complete when all of its tests pass.
- Golden-file tests verify that open-then-save reproduces files byte for byte.
- Selection, dragging, text editing and export are tested in real browsers (Chromium, Firefox, WebKit) with Playwright.
